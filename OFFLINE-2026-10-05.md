# Hors connexion — correctifs du 5 octobre 2026

## Site / PWA : suivi de classe et bloc-notes

Exécuter `schema_hors_connexion_4.sql` une fois dans le SQL Editor Supabase (ou appliquer la migration équivalente). Ce script conserve les lignes et les droits existants. Il nécessite les migrations hors connexion précédentes. Aucune modification distante de la base n'a été effectuée par la préparation de cette livraison.

Ensuite rouvrir le site avec Internet, laisser la préparation et la synchronisation terminer. Les observations, leurs modifications et leurs suppressions sont conservées dans IndexedDB puis envoyées au retour du réseau. Les répétitions sont recalculées depuis les observations conservées. Les documents de classe restent dépendants du réseau ; leur indisponibilité n'efface plus l'historique des observations.

Sans cette migration, le fonctionnement connecté reste disponible, mais une saisie hors connexion affiche explicitement qu'elle n'a pas été enregistrée. Préparer chaque appareil avant le cours ; ne pas se déconnecter ni effacer son stockage avant les envois.

Test navigateur avec données fictives : `node scripts/test-offline-class-notes.cjs`, après démarrage de `node scripts/serve-preview.cjs`. Vérifie création, modification, suppression, véritable rechargement sans réseau, répétitions, filtre de classe et reconnexion sans doublons.

## Android 1.3.7

- Les dispenses déjà téléchargées restent affichées si la lecture distante échoue. L'écran indique qu'il utilise une copie locale. Un échec d'envoi empêche une ancienne copie distante d'écraser les changements locaux en attente.
- Les modifications des tables Room déclenchent aussi un travail persistant WorkManager. Un envoi en cours n'est plus annulé par une nouvelle saisie.
- Une vérification périodique sert de sécurité. Elle ne relance pas l'échange si les révisions locales et la file d'envoi sont déjà confirmées. Les envois auxiliaires sont sérialisés.
- Android décide de l'heure d'exécution : fermeture normale possible, mais un arrêt forcé, les restrictions de batterie ou l'absence de réseau peuvent retarder la reprise. Une session expirée peut encore nécessiter une reconnexion. Ce mécanisme n'est pas une sauvegarde externe.

Validation : tests unitaires de cache, annulation et décision de reprise ; compilation APK. Le comportement après fermeture sur un téléphone physique reste à vérifier, sans écrire de données scolaires fictives sur le serveur réel.
